# Logicloom

Logicloom is a React/TypeScript code-intelligence prototype with a GitHub-backed analysis API. The existing workspace screens still include clearly labeled illustrative sample data; the live analysis panel is the path for actual repository scans.

## Local development

Requirements: Node.js 18.18+ (20 LTS recommended), npm, and a PostgreSQL database. Neon works as a hosted PostgreSQL option.

1. Install dependencies with `npm install`.
2. Copy `.env.example` to `.env` and set `DATABASE_URL`. Set a server-side `GITHUB_TOKEN` to analyze private repositories or raise GitHub API rate limits.
3. Create/update the local database schema: `npm run db:push`.
4. Start the Vite frontend and API together: `npm run dev:all`.
5. Open `http://localhost:5173`, use **Analyze repo**, connect an `https://github.com/owner/repository` URL, choose a branch, and run the scan.

Prisma Client is generated by `npm run db:generate` and during installation through Prisma's package lifecycle. To run only one process, use `npm run dev` for the frontend or `npm run dev:api` for the API. The frontend proxies `/api` to `http://localhost:3001`.

## Analysis scope and privacy

- The first analyzer supports JavaScript and TypeScript source files. It examines a bounded source snapshot (300 files and 10 MB by default; configurable with `MAX_ANALYSIS_FILES` and `MAX_ANALYSIS_BYTES`).
- Findings are reproducible heuristics, not compiler diagnostics, AST-based function complexity, test coverage, or a formal security audit. In particular, maintainability, quality, health, debt, and architecture scores are explicitly formula-based estimates; pattern matches require human review.
- Analysis snapshots persist source text in PostgreSQL so the code and line evidence can be retrieved later. Set appropriate database access, retention, and deletion policies before using private or sensitive repositories.
- A `GITHUB_TOKEN` is optional for public repositories and required for private repositories. It must remain in backend `.env`; never expose it as a `VITE_` variable.
- AI insights are optional and require `AI_BASE_URL` and `AI_API_KEY`. The backend sends the question and bounded analysis facts to the configured OpenAI-compatible provider. Without these settings the endpoint returns an explicit configuration error.
- Login and logout in this prototype are local demo UI only. The API has no user authentication or tenant authorization and is intended for local development, not public deployment.

## Checks

```sh
npm run build
npm run test:api
```

The tests cover import/dependency analysis, cycle detection, security-pattern evidence, and GitHub repository URL validation.
